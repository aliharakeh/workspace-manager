Overview

Topology: two clients, one hub

The CLI and the desktop app speak the same protocol to the same daemon. The daemon owns the runner, the database, git, blueprints and the AI; clients never write app state themselves.

request / reply line reply pushed event annotation

Try it: wm app list and the app window show the same data, because both read from the same daemon. Start a run in the window and wm logs <app> -f shows the same output.

Sequence 1 · launch

Cold start: the app dials the hub

The desktop app is a client before it is anything else: it dials, handshakes, subscribes to events, and only then loads the UI.

gui/main.go · gui/app.go · api/client · server/daemon

Sequence 2 · a page

Opening the workspace screen

A page load is a few request/reply calls; after that, updates are pushed events, with a slow poll as a safety net.

frontend/App.tsx · hooks/use-app-statuses.ts · host.ts · server/handlers

Sequence 3 · a run

Running an app from the UI

The click is one call; everything after it is pushed. The daemon applies templates, spawns the PTY, watches for the ready URL, and broadcasts.

server/services/runner.go · server/handlers/runner.go · frontend/hooks/use-runner-status.ts

Sequence 4 · the terminal

The Logs tab: catch up, then stream

Each terminal loads the buffered output first, then appends live chunks; offsets let it drop what it already has.

frontend/components/logs-panel.tsx · server/services/terminal.go

Sequence 5 · the CLI

The same run from the CLI

The CLI is the same client with a different face: dial (starting the daemon if needed), subscribe, act, and let an event or a timeout end the command.

cli/cmd/wm/runner.go · api/client · server/handlers/runner.go

Sequence 6 · git

Git tab: adding a worktree

One call does several filesystem steps; the reply carries the result and a dataChanged event tells every client to refresh.

server/services/git.go · server/services/worktreelinks.go · frontend/components/git-panel.tsx

Sequence 7 · AI

AI agent, review, then one write call

The agent runs in the GUI process and stages changes; applying them is a single call to the daemon, which owns the write path.

server/ai · gui/bind.go (AIAppChat, AIApplyPatch) · frontend/components/app-ai-panel.tsx
